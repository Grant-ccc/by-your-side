## 已实现的本地接口

- `GET /health`：数据库连通检查，AI 返回 `configured` 或 `not-configured`；已配置不代表真实调用成功。
- `GET /api/ai`：返回模型名称、配置状态、月度文字预算与预留；不返回密钥。
- `GET /api/conversations/:id/messages/:messageId/reply`：读取用户消息对应的回复状态，不生成、不扣费。
- `POST /api/conversations/:id/messages/:messageId/reply`：请求回复；可选 `{ retry: true }` 仅重试明确可恢复的失败。检查归属、并发锁、已有结果和预算。未知结果不自动重发。
- `GET /api/bootstrap`：幂等建立固定本地开发身份、角色关系和初始会话；仅本机使用。
- `GET /api/conversations`、`POST /api/conversations`：本地关系下的会话读取与新增。
- `GET /api/conversations/:id/messages?after=0&limit=50`：游标分页，校验资源归属与分页范围。
- `POST /api/conversations/:id/messages`：使用 `clientRequestId` 与 `text`；首次 201、同内容重复请求 200、标识冲突内容 409。保存后不伪装为角色已读或已回复。

请求使用 Zod 运行时校验。客户端保存结果不确定时保留同一标识重试；数据库约束与事务负责去重。本机 MySQL 已恢复。模型 HTTP、回复/费用事务与页面流程使用模拟模型验证，真实模型需另行验收。以下原规划仍有未实现部分。

## 基本约定

- 所有请求校验用户身份与资源所有权，不能只相信客户端提交的 user_id。
- JSON 输入做运行时校验，TypeScript 类型不能代替网络输入校验。
- 写请求使用幂等标识；分页/同步采用稳定游标。
- 服务端持有模型密钥，返回给客户端的数据不得包含凭据或完整调试提示词。
- 系统错误与角色消息区分，不把失败包装成人物冷落。

## M1—M2 最小接口

| 方法与路径 | 用途 | 关键行为 |
| --- | --- | --- |
| GET /health | 本地服务检查 | 不泄露配置/密钥 |
| GET /api/conversations | 当前用户会话 | 只返回有权限的资源 |
| GET /api/conversations/:id/messages?after=cursor | 初始历史与增量同步 | 有序、分页、返回游标 |
| POST /api/conversations/:id/messages | 保存用户消息 | 请求标识去重，返回 message_id 和处理状态 |
| GET /api/generations/:id | 查询等待/生成结果 | 重连可恢复，不因断线重复调用 |
| POST /api/messages/:id/regenerate | 最新回复重新生成 | 校验版本与范围、预算，替换后处理派生事实 |
| GET /api/usage | 用量与预算 | 区分预留、估算、已结算金额 |

可选的服务端事件流用于前台推送状态更新；断线后仍以数据库同步为准。是否逐 token 显示需要兼顾微信式分条体验，不能因为有流式模型输出就立即把半句话当正式消息保存。

## 关键处理流程

用户消息入库 → 根据作息进入待回复批次 → 执行时读取最新有效事实 → 预留预算 → 调用 AI → 校验结果 → 保存消息与用量 → 同步界面/尝试通知。

用户在忙碌期间继续发消息时，不为每条都立刻调用模型。进入陪伴模式时可以提前处理待回复批次；批次并发、取消和重试必须有明确状态。

候选约定需要日期和时间确认；“明晚”按用户时区解析，不能直接猜成某个固定时刻。冲突返回可解释信息，不静默挤掉旧约定。

## 失败与恢复

至少区分未授权、输入不合规、资源不存在、版本冲突、预算不足、图片额度不足、模型超时/失败、任务仍在执行等结果。客户端提供相应反馈，不能用统一“网络错误”掩盖所有问题。

重试前核对已有任务和费用。接收成功但尚未生成时，客户端显示等待，不重复发送同一内容。异步生成完成时间和设备实际收到通知时间分别记录。
